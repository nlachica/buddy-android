## Round 1 - Plan Reviewer (gpt-6.2-astra)

F1 [major] The phone check can mask the original symptom - Step 1 leaves Media at maximum, the same level as Call on the recorded phone (`plan.md:79-84`, `evidence-2026-11-22.log:44-51`). A later call can then sound loud and restore the expected index even if Buddy never raised it. Step 1 also proceeds if the keys already control Media, which removes the stated reason to mirror Call. -> Record both starting indices, use Auto with the watch off and headset disconnected, and press volume down once from maximum to see which index actually moves. Return both sliders to their starting values on every exit. Reconsider mirroring if the keys already change Media. Start the installed-build check with distinct indices and verify the speaker's Media index before, during and after the call alongside Nicholas's listening check.

F2 [major] A delayed restore can undo the user's newer volume choice - The plan saves only the original index and restores it unconditionally, potentially in a later voice session (`plan.md:53-61`, `plan.md:116-119`). If Buddy raises Media from 6 to 15, dies, and Nicholas later sets the speaker to 3, the next session writes 6 over his choice. The same loss can occur after a manual Media change during the call. -> Track the last level Buddy actually set alongside the original. Restore only while the speaker still has that level. If the user changed it, discard the stale restore. Test normal hang-up and restart after a manual change, including a restart with the headset connected.

F3 [major] Watch playback still raises the phone's system media volume - `plan.md:125-126` explicitly keeps mirroring while the watch plays. Muting the page silences only Buddy's phone output. Other apps on the phone still receive the raised volume, and the watch regression check at `plan.md:110-111` would pass anyway. `LiveWatch.java:254-258` already records when audio actually moves to the watch. -> Gate mirroring on phone playback as well as the confirmed speaker route. Check that the original speaker index is restored when the watch takes over and that mirroring resumes if the watch drops or comes off the wrist mid-call.

F4 [major] The timer can write a headset's volume during a route change - `plan.md:47-50` treats a route list containing the speaker as proof that the next stream-volume write targets it. Android documents this query as a prediction, allows multiple outputs, and allows routing to change concurrently. A headset can connect between the query and the write. The separate steady-state calls at `plan.md:110-111` miss that transition. -> Skip ambiguous, empty and mixed routes, recheck immediately before each write, and describe the residual race. Exercise headset connect, disconnect and hang-up during the same speaker call with distinct speaker and headset indices. Verify the headset index throughout. [Android AudioManager reference](https://developer.android.com/reference/android/media/AudioManager#getAudioDevicesForAttributes(android.media.AudioAttributes))

F5 [major] The proposed fallback cannot follow call volume on Android 12 or 12L during communication mode - Those releases run `AudioRoute.use()` (`AudioRoute.java:293-295`), but the fallback explicitly returns false in communication mode (`plan.md:47-49`, `plan.md:100-101`). It could take the volume during normal-mode setup and then ignore every key change while the call is active. Normal mode and absence of a headset also do not establish that media is on the speaker. -> Either provide a verified speaker check for API 31–32 or explicitly limit mirroring to API 33+ with confirmed speaker-only routing. For the latter, test that older releases leave Media untouched for the whole call and qualify the README promise at `plan.md:91-92`.

F6 [minor] The plan describes an earpiece fallback that the code cannot take - `brief.md:33-34` and `plan.md:4-5` say “earpiece last resort.” With no safe device, `AudioRoute.java:450-453` ends the call. Feature 033 already recorded the orchestrator's interim ruling on this exact case (`docs/features/033-watch-worn-audio/decisions.md:133-136`). -> Carry that ruling forward explicitly and identify the literal fallback as unresolved. Keep the phone-speaker fix scoped to the reported call.
