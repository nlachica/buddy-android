## Round 1 - Code Reviewer (gpt-6-astra)

F1 [major] A queued scroll restoration can crash after the next snapshot replaces its rows - `wear/src/main/java/app/buddy/assistant/wear/TalkActivity.java:392-400` captures an anchor index for one snapshot, then dereferences that index in the mutable `history` container in a posted callback. Two accepted snapshots can already be queued by the listener at `:92`: A rebuilds the rows and posts its scroll, B rebuilds them again, then A's scroll runs against B's children. A byte-budget shrink makes this a real out-of-range access: start with 24 short rows followed by six roughly 9 KB rows, scrolled to short row 20; the user's short message produces A with 30 rows and retained anchor 19, then a long reply produces B with only seven rows. `history.getChildAt(19)` is null, so `.getTop()` crashes. Even without a shrink, A's index can refer to a different message. Android's [View.post implementation](https://github.com/aosp-mirror/platform_frameworks_base/blob/master/core/java/android/view/View.java) queues the callback; [ViewGroup.getChildAt](https://github.com/aosp-mirror/platform_frameworks_base/blob/master/core/java/android/view/ViewGroup.java) returns null for an absent index. -> Make pending restoration belong to the latest rendered snapshot and preserve the original visible-row anchor across a burst until layout completes (coalescing the pending snapshot/render work is another small option). Cancel or invalidate superseded callbacks; do not use an index from a replaced row set. Add a regression with two accepted snapshots before the first restoration, including a byte-budget shrink, checking both no crash and the retained-row/top fallback. The existing pure `anchor()` tests cannot exercise this scheduling bug.

F2 [minor] Speech failure marks the error as a mirrored reply and leaves the actual reply unmarked - `wear/src/main/java/app/buddy/assistant/wear/Talk.java:351-352` sets `mirror` on the last line only after `say()` returns. But `say()` calls `pump()` and `speak()` (`:457-489`); if `tts.speak()` returns `TextToSpeech.ERROR`, `speak()` appends a watch-only `talk_no_voice` line and invokes `changed()` before returning. The new assignment then marks that error instead of the reply. With the reply's snapshot already displayed, `below()` draws the reply a second time and hides the new speech error, reversing both intended classifications until another snapshot arrives. -> Mark the exact reply line as mirrored when it is created, before speech can append a line or trigger a redraw; keep watch-only errors unmarked. Add a regression for a reply received after its snapshot when speech immediately fails, asserting one displayed reply and a visible watch-only error.

### Coder response (round 1)

F1: fixed in the commit "fix(022): review round 1". The reading place is captured once per burst: while a restoration is pending (`placePending`), a later snapshot keeps the first one's rows, top index and offset instead of reading the not yet laid out views. Each snapshot takes a ticket (`restore`); a superseded callback returns, and the last one computes `anchor(placeRows, placeTop, rows)` against the newest rows, so no index of a replaced row set is dereferenced (`anchor` returns -1 or an index inside `rows`; -1 scrolls to the top). Test: `aRetainedAnchorStaysInRangeWhenTheRowsShrink` (30 rows to 7: left row gives -1, a kept row its new index). The scheduling itself (two snapshots before the first `post` runs) is view code and is not covered by a JVM test; it is a hardware check for the Verifier. I did not coalesce the snapshot work: not needed.

F2: fixed in the same commit. `say(kind, text, voice, mirror)` sets `mirror` on the Line before `pump()`/`speak()` can add `talk_no_voice` or redraw; the two lines that set it afterwards are gone, watch-only errors stay unmarked. Not unit-tested: `Talk` needs a Context and TextToSpeech, and the wear module's JUnit covers only pure statics (decision "Unit tests in the wear module"); a speech failure on a received reply is a Verifier device check.

Local `./gradlew :wear:testDebugUnitTest` still can't start here (JVM: "Failed to mark memory page as executable"), so the new test and the changes are unrun; CI is the check.
